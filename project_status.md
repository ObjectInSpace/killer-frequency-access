## How targeting works now

`KillerFrequencyAccessMod.Interactables.cs`:
- Discovery: `FindObjectsOfType<Il2Cpp.InteractableBase>()`; listed when active, not `OculusOnly`,
  and at least one of its `Il2CppActions.InteractionBase` components reports `Available`.
- Actions: the interaction's Il2Cpp class name through a fixed verb table (every class in the rip),
  ordered by `Priority`. An unknown class is spoken by class name and logged.
- Names: `Generated\GameObjectNames.cs`, generated by `tools\rip\gen_names.py` from the rip, keyed
  by full hierarchy path; prefab name plus a role from its components (door, handle, button,
  holder, board item). Fallback: a leaf name that maps to one name only; else the raw name, logged
  as `[names] not in GameObjectNames`. Review list: `docs\rip\spoken_names.txt`.
- Player: the `ControllerBaseInteractor` (on `PlayerController`, which also has the
  `CharacterController`; one per scene). It is the navigation origin.
- Pointing at: `ControllerBaseInteractor.observedInteractable`. Auto-walk stops when the game reports
  the target as observed; "in reach" is the camera within the target's `fsMaxReachDistance` of
  its nearest `m_Colliders` entry.

`KillerFrequencyAccessMod.ObjectList.cs` (object list, modelled on Date Everything Access's picker):
- O opens or closes it. Page Up / Page Down move, Enter goes in (rooms, then categories, then
  objects), Backspace goes back a level (closes at the top). Choosing an object sets the room and
  category that `[` / `]` cycle through; Backspace with the list closed still auto-walks.
  Keys are ones the game's `InputActions` asset leaves unbound (the arrows are movement).
- Rooms: the game's 25 `Il2Cpp.Room`s; a point is in a room when one of `Room.volumes` contains it.
  Name = floor folder + room object ("Ground Floor Break Room"). Room levels: current room (follows
  the player), all rooms, each room. Entering a room is announced.
- Categories: the game's component on the object, first match wins: story items
  (`StoryObjectCheckpoint`, or `PhysicsHoldable.onHeldStoryEvents` set), collectables
  (`CollectInteraction`), doors, drawers, buttons, sliders, cassettes, floppy disks, records, fuses,
  tray items (`DockableInTray`), pinboard items, sticky notes, holders, objects (`PhysicsHoldable`), other.
- No cap on the cycle list (it was the 14 nearest objects). Each entry says "N of M".
- Actions spoken for the object you point at use `CanPerform(interactor)` (first run: `Available`
  was true for drop and throw on items not held). Every spoken line is logged as `[speech]`.

Still old code, not yet rebuilt: the environment scan tones (raycast open-path probing, to be
replaced by step 8) and NavMesh waypoint search in auto-walk.

## Findings (2026-11-04)

- The game is a radio station the player walks around in first person, with desk scopes (mixer,
  pinboard, record drawer). See `docs\game-api.md`.
- The game has two interaction systems in code. The scenes use Radio.Actions
  (`Il2CppActions.Interactables.Interactable` with `Il2CppInteractables.*` actions).
  `Il2Cpp.InteractableItem` and the `RootScope`/`DeskChairScope`/... scopes are never placed in any
  scene or prefab.
- SCN_Main has 804 interactables; SCN_Intro 51, SCN_Epilogue 46, SCN_Menu 6. Lists:
  `docs\rip\interactables_*.txt`.
- Every `interactionScope` field in the scenes is null; scope must come from the runtime.
- The game names no objects anywhere: the reticle is an icon, and the localization tables in the rip
  are UI text only.
- NavMesh: SCN_Main uses `NavMesh_0.asset`, Intro and Menu `NavMesh_1.asset`, Epilogue `NavMesh.asset`.
- SCN_Main has 25 `Room`s, 17 `RoomPortalDoor`s, 59 `DoorOpenable`s.

8. Audio guidance, after targeting works. Model it on Date Everything Access (`ObjectTracker.cs`,
   `AccessibilityWatcher.AimCoach.cs`), not Before the Storm (third-person, speech-only clock
   directions): one continuous tone for the selected target. Walking: pulse rate = distance,
   stereo pan = heading error, one-shot chirp at landmarks (doors). Aiming (steady tone): pan =
   horizontal error, pitch = vertical error, chirp when the game's own selection is the target.
   Spoken aim coach as the alternative ("a little up", "far left"). Settings: tone or spoken.
   Replaces the old environment-scan tone code. First-person desk scopes (mixer, pinboard) may
   want aiming help more than route guidance. Paths can use the game's NavMesh.
